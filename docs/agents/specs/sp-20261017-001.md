# Vampire Survivors 超小原型

## 1. 当前行为（证据）

仓库为空，没有任何可运行程序。`git ls-files` 无内容。

## 2. 期望行为 / 验收标准

| # | 标准 | 怎么判定 |
|---|---|---|
| ac1 | 960×600 窗口，暗色地板 + 网格，镜头跟随主角并夹在 2400×2400 场地内 | 像素：地板 RGB 和 < 130；`render.camera` 单测 |
| ac2 | 主角是浅红菱形（正方形旋转 45°），230 px/s，被夹在场地内 | 像素：屏幕中心 == PLAYER_FILL；单测夹紧 |
| ac3 | 敌人是白色圆形，恒定 65 px/s 朝主角移动，每 0.55s 生成一个，生成点距主角 ≥ 390px | 像素：敌人圆心 == ENEMY_FILL；单测速度 63–67px/s、生成距离 |
| ac4 | 自动攻击：每 0.45s 向 420px 内最近敌人发射蓝色子弹（560 px/s，15 伤害） | 像素：子弹 == BULLET；单测"打最近"、单测击杀 |
| ac5 | 子弹 2 发击杀一只（敌人 30 血）；击杀计数 | 单测：击杀后 `enemies == []`、`kills == 1` |
| ac6 | 接触扣 12 血，0.6s 冷却；全局没有任何回血 | 单测：冷却期内不重复扣血；单测血量单调不增 |
| ac7 | 血量归零 → 立即失败，状态冻结，不再推进 | 单测：`state == "lost"`，再 step 快照不变 |
| ac8 | 180 秒到点 → 清空场上敌人与子弹、判胜、计时停在 180.0 | 单测 `duration=2`；无头验证完整 180 秒 |
| ac9 | 同 seed + 同输入 → 完全相同的快照 | 单测 600 帧比对 |
| ac10 | 无头验证可在无显示器环境跑完，产出 3 张截图 + JSON 报告，退出码反映结果 | `scripts/verify.py` |

胜负同帧时**判负优先**（血归零是即时事实，到点是边界条件）。

## 3. 实现思路

拆三层，让"能验证"成为结构属性而不是事后补测试：

- `world.py`：纯逻辑，不 import pygame、不读时钟 → 可在无头环境跑 10800 帧，可重放。
- `render.py`：纯绘制，状态只读 → 颜色常量可被验证脚本直接比对。
- `app.py`：输入与主循环 → 单独做 60 帧冒烟。

被否方案：把逻辑写在 `app.py` 的主循环里。理由：那样每次验证都要开窗口、等真实时间，180 秒验证要跑 3 分钟且不可重放。

## 4. 不做什么

见 `non_goals`。特别地：不做升级系统——它会立刻引入"数值平衡"这类无法自动验收的问题，不适合作为流水线的第一个样本。
