# verify-game

## 为什么需要它

单元测试只能证明 `World.step()` 算得对。它证明不了：窗口开得起来、地板是暗的、主角画成了菱形、敌人是白的、子弹是蓝的、血条真的在屏幕上、180 秒到点真的会赢。

这些只有**把程序跑起来看**才知道。这个技能就是"看"的方式：无头运行 + 截图 + 读像素。

## 怎么跑

```powershell
uv run python scripts/verify.py
```

- 不需要显示器（`SDL_VIDEODRIVER=dummy`）
- 3 秒内跑完，包括完整 180 秒模拟
- 退出码 0 = 全过；1 = 有失败
- 证据：`artifacts/verify/<时间戳>/`（3 张截图 + `summary.json`）

## 检查项在验什么

| 检查 | 证明什么 |
|---|---|
| 窗口尺寸 | 渲染目标没被改坏 |
| 开局 3 秒仍在运行 | 状态机没一开局就结束 |
| 敌人已生成 / 已自动开火 | 刷怪与武器逻辑真的在跑 |
| 地板是暗色 | 背景没被写成白/透明 |
| 血条已绘制 | HUD 没画到屏幕外 |
| 主角浅红菱形 | 玩家渲染的颜色与形状 |
| 敌人白色圆形 | 敌人渲染 |
| 子弹蓝色 | 投射物渲染 |
| 到点判胜 / 清空敌人 / 计时停住 | 胜利分支 |
| 站着不动会死 | 伤害与失败分支 |
| 完整 3 分钟 | 真实时长下不崩、能结束 |
| 满时长仍有击杀 | 武器在整局都在工作 |
| 同 seed 可重放 | 逻辑无隐藏随机源 |
| 真实入口 60 帧 | `app.py` 主循环可启动可退出 |

## 加一个检查

1. 在 `scripts/verify.py` 里加代码，**只加不减**
2. 失败信息要写清"看到了什么"（把实际值放进 detail）
3. 如果检查需要新的截图，存到同一个 `OUT` 目录
4. 跑一遍，确认新检查在"故意改坏"时真的会失败（例如把 `FLOOR` 改成白色，看它红不红）

新增检查必须能对上一个真实可能发生的错误，否则是噪音。

## 失败怎么判断

| 现象 | 结论 |
|---|---|
| 截图存不出来 / 全是黑 | 渲染或驱动坏了，先修环境 |
| 像素颜色对不上 | 渲染改动导致，不是逻辑问题 |
| 状态断言失败（won/lost） | 逻辑问题，去看 `world.py` |
| 真实入口冒烟失败 | `app.py` 或事件循环坏了 |
| 运行超过 30 秒 | 有 O(n²) 退化，看 `_move_bullets` |

## 禁止

- 只跑 `pytest` 就说"游戏没问题"
- 为了变绿而放宽颜色比较或删检查
- 用真实窗口当唯一证据（人看得见、CI 看不见）

## 完成标准

- [ ] `scripts/verify.py` 退出码 0
- [ ] 至少看过一遍生成的截图（不是只看 PASS）
- [ ] 新增检查时，验证过它能抓到预期的坏改动
